## 1. 项目定位

MedEvidence 是以本地医学知识库为底座的研究型证据分析系统。目标是接收医学问题或病历、体检报告的文字，围绕肿瘤相关问题与综合医学问题检索原始资料，生成可追溯的分析报告，并明确缺少的证据与患者信息。

优先建设可靠入库、双语检索、原文引用和有限 Agent 工具流程。最初讨论过医生/科研人员查证、个人健康咨询及肿瘤风险分析；这些是目标场景，不代表已完成临床产品验证。当前支持的输入以文字为主，不具备成熟的患者 PDF/影像接收与临床结构化管线。

项目的医疗代码位于独立的 MedicalEvidenceAgent 工程；历史协作曾在另一个工作目录中进行，不能把那个项目的销售/建材助手能力算作本项目成果。建材助手仅作为会话记忆的工程参考。

## 4. 正在开发与已确认问题

### 4.1 多轮追问：当前首要问题

已接通“当前问题独立整理→必要时召回上一条用户消息与语义Top3→语言补全→两路取证”。第一步不向模型传入历史对话。历史向量复用 BGE-M3，缓存绑定作用域、模型身份及原文哈希。

但**真实省略追问回归未通过**：历史可以召回，模型仍可能保留残缺问题、替换错对象，或在存在相关历史时要求澄清。已经拦截“原句未补全却标记 resolved”的情况。当前补全角色尝试使用现有8B；不是新增第三套常驻权重，也没有证明比4B更可靠。

完整新问题在一个真实服务样例中未调用历史补全；这只能证明该样例隔离成功，不能推出所有独立问题均不会被污染。历史问句不自动变成患者事实；相关患者事实的自动选择尚未接入新通道。

### 4.2 医学回答质量

已有报告记录了限定条件遗漏、关联被写成因果、偏题证据误放、表格选错行等问题。最终审核模型也会误判；精确引用和模型支持性检查不构成临床正确性证明。部分宽泛问题仍只有证据缺口说明，未形成有效医学回答。

### 4.3 运行与评测

- 单机服务面向可信本地管理员；不能宣称已完成企业多用户认证、互联网部署或生产高可用。
- 图运行使用进程内 checkpoint；运行记录会落盘，但进程中断后不会自动重放整条 Agent 流程。入库断点恢复是另一套已实现机制。
- 旧版日志中的414项通过是工程契约测试；其中一个本机 TestClient 生命周期用例阻塞，另用真实HTTP检查部分生命周期。不能称所有HTTP回归均通过。
- 新版本私有运行记录保留实际HTTP推理请求、返回/失败与耗时，并另计成功序列回执；部分失败没有生成token回执，不补造t/s，图节点数也不等于实际生成序列数。旧版本缺少的记录不能事后冒充已保留。
- 冷启动、检索、token生成、格式重试和补检均影响耗时；尚无充分的长期P95和临床语义基准。

## 6. 下一步顺序与完成标准

1. **单独验收语言补全器**：冻结中英独立问题、指代、省略、对象替换、否定、更正、歧义及前轮失败场景；检查原文锚点和真实语义，而非只看JSON合法。
2. **补上独立的相关事实通道**：仅按当前问题取用仍有效的事实；当前更正优先；不得用助手答案替代患者原话。
3. **改善来源适用性与表格行选择**：分开定位资料缺失、查询偏差、切片、重排、读取和总结错误；用完整原文人工抽查。
4. **扩展固定回归**：分别报告检索覆盖、支持性、条件保留、回答完整性及耗时；保留失败与未回答样例。
5. **确认增益后再扩库/恢复标签实验**：不以全量抽实体、微调或换大窗口代替当前链路验收。

### 当前默认：程序压缩导航、选择与Leader分开

按用户后续明确的职责，中间步骤只负责选择、复核与补检，不生成医学分析。默认由程序提取原文句群并去重，4B不再逐块写摘要；两路4B输出保留/待定/偏题建议，各路Leader再独立复核证据、缺口和工具动作。它们复用既有4B权重，未增加常驻模型。8B仍按来源ID取完整原文，保留完整优先/超限提取/仍超限分批完整阅读。
